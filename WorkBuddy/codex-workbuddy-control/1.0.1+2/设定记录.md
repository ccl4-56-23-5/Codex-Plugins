# WorkBuddy Control 设定记录

## 2026-11-16 · 1.0.1+2

- 用户要求逐项解决组会 QA 记录中的旧任务续写失败、草稿导致停止按钮被隐藏、账户弹层遮挡分组菜单、点击后返回旧界面四项问题，覆盖安装并替换 GitHub 版，核验完成后清理原 QA 目录。
- 旧任务续写用真实输入，必须确认编辑框的焦点或可见光标，发送前再核对完整草稿。清空草稿需要核对当前内容；仅在 WorkBuddy 显示取消或等效状态时报告生成已取消。
- 账户遮挡先关闭已识别弹层并刷新索引。提交、换模型和换分组应观察对应的结果，不能以点击返回作为成功凭据。Esc 中止电脑操作不代表 WorkBuddy 后台任务已停止。
- 本节覆盖首版「只能由用户填写已有会话草稿」的兼容说明，以及维护文档中的旧仓库地址。

## 2026-11-15 · 1.0.0+1

- 用户要求制作、安装由 Codex 控制 WorkBuddy 的插件，并同步 GitHub。沿用既有 `Codex-Plugins` 仓库。
- 本次采用 Windows Computer Use 与本机任务链接组合。首版交付包括新任务、可见任务导航与回复读取、发送及停止生成。允许从当前可见状态继续操作。
- 新任务用正常的 WorkBuddy 输入与发送流程。发送前核对草稿。点击之后以真实会话回执、完成或取消状态为准。
- 待处理的兼容性问题是 WorkBuddy 5.11.3 已有会话编辑器的焦点报告。使用者可先在 WorkBuddy 填好草稿，由插件核对并发送。
